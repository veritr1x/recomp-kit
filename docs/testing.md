# Testing

`openal_tests` captures mixer calls and advances the guest clock to check
source progress, processed queues, shared-context buffer lifetimes, stable
pitch/pan, all six distance models, format/rate refusal, null upload bounds,
multichannel folding and device cleanup. Bink tests in `dx_tests` cover the
legacy/SDK records, registered Y/cR/cB planes, seek back to frame one and
full summary/realtime guards with `RECOMP_TEST_BINK_CONTAINER=host-path,offset`.
Use a colored fixture to establish sensitivity to swapped chroma planes.
`RECOMP_TEST_BINK_MEMORY=host-path` additionally checks a real Bink movie
through the guest-memory window; that optional media file stays outside Git.
The binary's `RECOMP_TEST_AUDIO` mode exits after its decoder check, so run it
separately from the Bink suite. CI generates an AVI fixture and Ogg tone for
these separate runs. [Audio compatibility](audio-compat.md) lists limitations.

`crt_tests` exercises the VC8 imports through guest ABI calls: allocation and
overflow refusal, sort callbacks, UTF-16 strings, integer and floating-point
conversions, x87/MXCSR control, printf/scanf and legacy NaNs, secure truncation,
file operations through a temporary resolver, stable descriptors across many
opens, startup data, environment, ctype, exit tables, time, char/wchar_t C++
strings and CRT thread exit/errno cleanup. Child processes exercise Unicode
argv/environment round trips through CRT and Win32 (surrogate pairs included).
They also check named aborts
for out-of-arena memory and file transfers, multiplication overflow, unknown
required imports and unbounded format widths. `msvc_eh_tests` additionally
catches a CRT string position exception by value through a live checkpoint.
`test_translate_driver.py` checks CRT IAT calls and initializer jump thunks.
See [CRT compatibility](crt.md) for supported layouts and current limits.

`msvc_eh_tests` runs typed/ellipsis/reference/value catches, base and virtual-base
adjustments, copy constructors, nested cleanup, rethrow and replacement throws
through the guest import ABI. Subprocesses check uncaught type diagnostics,
stale/missing checkpoints, double throws and foreign callback barriers. A C
fixture generated by the production translator catches, resumes its local
continuation, unlinks the frame and returns its expected registers. The suite
also checks SEH-record dispatch, handler4 pass-through, full longjmp values,
checkpoint retirement, exception RTTI and data-import initialization after an
arena reset. Translator tests cover LEA/ESP publication, omitted funclets and
continuations on both return paths; cleanup-only frames get no checkpoint.

`d3d9_warm_tests` checks queued takeover, concurrent builders/waiters,
abandonment during failure/unwind, pool shutdown, canonical pipeline inputs,
bounded hint parsing, file damage recovery and concurrent atomic rewrites.
The D3D9 device suite checks that shader creation announces both GPU programs,
and does not announce CPU-only or refused shaders. Metal readback tests repeat
with saved, stale and swapped-role hints and with warming disabled.

`d3d9_device_tests` checks shader bytecode bounds, immutable copies, COM
binding/device lifetimes, GetFunction/GetDevice, creation parameters and
CPU instancing across streams 1-7 with dividers one and two. It also checks
the GPU draw seam's instance metadata, all shader source generators and the
render-scale base rule. `d3d9_gpu_tests` reads back instanced colors and screen
derivatives on the selected GPU backend; Metal additionally checks SM3 pixel
position/face and dividers above one. Vulkan checks clean skips for unsupported
dividers and misc inputs. WGSL source emission has no browser execution check.

`guest_memory_tests`, `guest_memory_2gb_tests` and `guest_memory_aux_tests` check readable arena edges
and subprocess faults above the accessible range, including accesses across
the highest 32-bit address. The auxiliary layout check keeps a high module's
marker intact while writing to every runtime region below it. Config tests
cover high DLLs, low DLLs, reserved-region collisions and full-size layouts
without high DLLs. `null_guard_tests` checks all scalar accessors
with debug guards disarmed and armed. `hardening_tests` checks mutation
refusal without an overlay, profile confinement, canonical symlink escapes
(when the host permits creating links), and absolute opt-in mod roots.
`hardening_release_tests` verifies that disabled developer loaders ignore
library environment switches. Web CSP/staging and macOS entitlement checks
run in the portable tooling suite; node tests cover URL environment injection.

`runtime_tests --mm-timers-only` runs without a game image and is registered
as the `nogame` suite `runtime_mm_timer_tests`. It checks worker callbacks and
event timers without a message loop, callback cancellation/replacement,
worker exit/restart, periodic cadence, pinned time and shutdown.

`message_tests` checks window ownership, thread-specific quit messages,
PostThreadMessageA/W and a helper's empty GetMessage loop without host ticks.
`startup_tests` checks allocation granularity, name/temp buffer sizing,
shell32 quoting and LocalFree ownership, dotless file searches and the entire
shim capacity. Quoting golden cases were verified with Windows shell32.

`scheduler_tests` checks progress from import-free loops within two budget
polls, the 4096-edge budget, atomic protection, host-thread exclusion, a
20 ms waitable-timer deadline and 16 workers making repeated exclusive
handoffs. `test_translate_backedge.py` checks branch/dispatch emission and
that generated local gotos share one helper.

`vector_tests` pins MXCSR rounding, conversion exception status and integer
indefinite values (including FISTTP) against architectural constants. The
synthetic instruction differential suite also covers packed/scalar SSE1,
MMX conversions and x87 conditional moves/tags on POSIX hosts with Unicorn.
Unicorn omits SSE conversion status flags, so those bits are checked in
the native suite separately. RCP/RSQRT use exact reciprocals; differential
inputs for these are exact powers rather than hardware-estimate bit patterns.

`loader_module_tests` maps hash-verified synthetic DLL files, checks relocated
memory and IAT binding with the importer mapped first, then exercises dependency
attach/detach order, reload, cycles, failed initialization and static pinning.
With a high-module game configuration it also maps and relocates a synthetic
DLL above `GUEST_LAYOUT_END`, while refusing heap, stack, shim and image overlap.
It runs without game files under `nogame`. `test_translate_relocate.py` checks
PE32 relocation validation and generated module output at its new base.

`hardware_tests` checks configured desktop, display enumeration, adapter
identity and memory through the guest API. `guest_layout_tests` checks
both root/nested EXE layouts, the suffix-mismatch fallback, DLL/command-line/
environment paths and ANSI/wide full-path normalization. Both run without
a game image under `nogame`; launcher tests also import a nested EXE install.

`d3d9_raster_tests` checks CPU pixels for integer sample centres, shared
triangle edges, viewport clipping, depth formats/comparisons/clears, alpha
comparisons, blend operations/factors, color masks and texture addressing.
It runs without game files under the `nogame` label.

`d3d8_tests` exercises the Direct3D 8 guest vtables, stack cleanup, structure
sizes, resource ownership, shader handles and actual CPU draw pixels.
`d3d8_program_tests` checks FVF/declaration decoding, bounded shader parsing,
constant binding and fixed-function combiner colours. Both carry the `nogame`
label. `host_tests --d3d9-gpu` runs the same combiner cases on the active GPU
backend (Metal on Apple platforms, Vulkan on Windows/Linux). These are
offscreen correctness checks; they do not establish game compatibility or
playable performance.

The `gpu` label includes `d3d9_gpu_tests` (`host_tests --d3d9-gpu`), so the
Direct3D 8 combiner cases also run in the Metal and Vulkan CI jobs.

Run checks appropriate to your change. Every suite's output belongs under ignored
`build/`; requested tests must report failure rather than silently skip prerequisites.

| Command | What it checks | Needs game files? |
| --- | --- | --- |
| `tools/test.py` | Setup failures, synthetic texture processing and display-mode tooling | No |
| `tools/format.py` | Consistent formatting of handwritten native code | No |
| `tools/test.py --compile-only` | Every native test binary this platform has compiles (macOS, Linux, Windows) | No |
| `tools/test.py --native` | Portable suites everywhere; runtime, adapters, offscreen Metal and UI tests on macOS | Partly: `game`-labeled suites need the image |
| `tools/test.py --mods` | Real loader/hooks/settings/native Options and replay contracts | Yes, plus translated archive |
| `tools/test.py --gameplay` | Menu navigation, mode cycling, selection, movement and clean exit | Yes, plus translated archive |

Native suites are CTest entries with labels: `nogame` runs everywhere and in CI,
`game` needs your installation, `gpu` needs a Metal device, `device` needs a
real Metal and audio device (the offline audio render is not what a hosted CI
runner produces), `mods` needs the translated archive and the entity snapshot `tools/test.py --mods` captures. Run
one directly with `.venv/bin/ctest --test-dir build/cmake/macos -L nogame` or `-R dx_tests`.
Two suites cover the on-screen controls, both `nogame`: `controls_tests` for the
layout model, geometry, routing, virtual pad, mapped binding, raster primitives
and editor (including the old keypad geometry as a regression oracle), and
`pad_tests` for the DirectInput joystick and the three XInput DLLs, which lives
beside `dx_tests` because it defines the `host_pad_*` callbacks strongly.
`runtime_pulse_tests` also runs without game files: synthetic guest threads
check that a manual-reset pulse releases all waiters, an auto-reset pulse
releases one, and a pulse with no waiters leaves the event unsignalled.
Every `tools/test.py` mode takes `--game-dir /abs/path/to/<game>`; without it
the kit's stub game is used and the `game`-labelled suites report a skip.

Invoke these with `.venv/bin/python`. The native tests need a macOS Metal device;
CI compiles them but does not claim GPU or original-game execution. The mod suite
first builds and runs a deterministic 32-frame entity capture from your own game
in an isolated directory; no saved capture from another checkout is needed. The gameplay
runner uses an isolated profile and original textures unless a local pack exists.

For a Windows cross-build, set `LLVM_MINGW_ROOT`, then run
`tools/build.py --preset windows-cross --stub --target app` and
`tools/test.py --preset windows-cross-stub --compile-only`. CI verifies the
Indeo 5/AVI and Vorbis/Ogg components and uses Wine to load `dx_tests.exe` with
only its three copied FFmpeg DLLs. `RECOMP_TEST_AUDIO=/path/to/track.ogg` exercises
the CD-music decoder and requires nonzero PCM; CI generates its own sine tone.
`RECOMP_TEST_AVI=/path/to/movie.avi` exercises the guest AVIFile/Indeo imports,
requiring changing nonblack frames. Movie probes use private local inputs,
never uploaded. These headless probes do not open an audio device or game window.

For instruction-translation changes, use the original differential harness:

```sh
.venv/bin/python tools/recomp/tests/test_translate.py --help
.venv/bin/python tools/recomp/tests/test_translate.py
.venv/bin/python -m pytest tools/recomp/tests/test_translate_hooks.py
```

Three translator suites need no game and run in `tools/test.py`:
`test_translate_insns.py` runs synthetic listings of individual instruction
forms through the translator, compiles them with the test harness and
compares registers, flags and memory with Unicorn; `test_jumptables.py`
decodes the jump-table shapes on synthetic functions over a fake image;
`test_translate_driver.py` covers driver rules such as what a withdrawn block
leaves behind. Add a case there first when the translator meets an
instruction or table shape it does not handle.

The differential harness compares translated routines with original instructions
under Unicorn. Unicorn is a development tool, not part of the playable app.

## Manual gameplay checks

- Start a level, select a person, issue a move order and observe the destination.
- Compare Classic/Enhanced and Wide on/off in a window wider than an 800×600 canvas.
- Cycle resolution through 640×480, 800×600 and 3840×2160, then resume play.
- Change graphics/host settings, quit normally, relaunch and check persistence.
- Test Command-Q, focus loss/return and mouse motion at all four edges in each window mode.
- Play the intro long enough to expose streaming stalls; check music and effects in a level.
- Compare animation speed at 60 and 120 FPS. Capture frame-pacing data during real play.

Report macOS/device, selected resolution, window mode, rendering mode and frame
limit. State whether FPS counts submitted, completed or displayed frames. A pinned
smoke clock is deterministic test timing and cannot substantiate real-time performance.

## Current local evidence

The source snapshot includes fixes exercised through native Options, live
640×480 → 800×600 → 4K → 640×480 transitions, unit movement and clean exit.
The initial publication additionally runs the source-only CI checks and local
native suites built through CMake from the standalone checkout, and the Linux and
Windows portable-layer suites in CI. Long campaign completion, multiplayer
and sustained 4K120 remain unverified; publish measurements with their conditions.
